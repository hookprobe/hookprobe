# `security/slsa/` — build provenance (SLSA)

> **Readme "Provenance" / ADR 0002: build with SLSA-style provenance so every artifact
> traces back to a commit and a pipeline.** This is the third leg of the supply-chain
> moat, alongside the SBOM and CBOM.

## What we attest

For every published artifact (OS image, each module, each disk image) the build emits a
**SLSA provenance** statement binding the artifact digest to:

- the **source** (repo + commit SHA + ref),
- the **builder** (the GitHub Actions workflow identity + runner),
- the **build parameters** (PROFILE, TARGETARCH, base image digest, toolchain versions),
- the **materials** (pinned base image, wasmtime/cosign release digests).

The provenance is attached to the artifact as a cosign attestation
(`predicateType https://slsa.dev/provenance/v1`) so `cosign verify-attestation --type
slsaprovenance` (or the SLSA verifier) can confirm "this image was built by *that*
workflow from *that* commit," not side-loaded.

## How (two viable mechanisms — pick one in CI)

1. **GitHub Actions OIDC + the official SLSA generator / `actions/attest-build-provenance`.**
   The simplest path on GitHub-hosted runners; produces SLSA Build L2-ish provenance
   keyed to the workflow's OIDC identity (pairs naturally with **keyless cosign**).
   Used by `build-os.yml` / `build-modules.yml` via the `attestations: write` permission.
2. **In-toto + cosign attest with a KMS key.** For the offline/regulated release line
   (pairs with **KMS/HSM cosign**, ADR 0002). Generate the in-toto predicate in-pipeline
   and `cosign attest --predicate provenance.json --type slsaprovenance --key <kms>`.

## SLSA level — honest target

- **Achievable now (GitHub-hosted):** ~**Build L2** — signed provenance, hosted build
  service, non-falsifiable by the workflow author.
- **Build L3** needs an **isolated, ephemeral builder** with the provenance generated by
  a trusted control plane the build job cannot tamper with. The official reusable SLSA
  generators get close on GitHub; the privileged `bootc-image-builder` step (runs
  `--privileged`) and any self-hosted arm64 runner are the parts to scrutinise.
- **Reproducible builds** (Readme threat model) are a *separate* property from SLSA and
  require pinned toolchains + SBOM determinism (see `security/sbom/README.md`).

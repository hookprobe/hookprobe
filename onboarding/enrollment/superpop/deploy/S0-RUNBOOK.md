## Steps

1. **Build** (on fortress; cross-built and self-tested 2026-11-22):
   ```bash
   cd onboarding/enrollment/superpop
   CARGO_TARGET_AARCH64_UNKNOWN_LINUX_GNU_LINKER=aarch64-linux-gnu-gcc \
     cargo build --release --locked --target aarch64-unknown-linux-gnu
   qemu-aarch64-static -L /usr/aarch64-linux-gnu target/aarch64-unknown-linux-gnu/release/superpop selftest   # PASS
   ```
2. **Firewall source**: merge `deploy/setup-vrf-g19.nft` into `hookprobe-com/scripts/setup-vrf.sh` at the marked
   positions (a PR in hookprobe-com). On the A1, after deploying it: `sudo systemctl restart hookprobe-vrf.service`
   and then `sudo python3 scripts/security-patch.py`. Check with `sudo nft list chain inet hookprobe_vrf input | grep 7654`.
   The rules are proven in `deploy/tests/vrf-g19-e2e.sh` (unprivileged, 11/11; a weakened ruleset fails it).
3. **OCI security list**: add ingress UDP 7654–7655 from 0.0.0.0/0 to the A1's subnet (console; there is no `oci` CLI here).
4. **Install on the A1**:
   ```bash
   sudo useradd --system --no-create-home --shell /usr/sbin/nologin superpop
   sudo install -m 0755 superpop /usr/local/bin/superpop
   sudo install -m 0755 superpop-net.sh /usr/local/sbin/superpop-net.sh
   sudo install -d -m 0750 -o superpop -g superpop /etc/superpop
   sudo -u superpop /usr/local/bin/superpop keygen --key-file /etc/superpop/pop.key    # 0600; prints the public blob
   sudo /usr/local/bin/superpop pub --key-file /etc/superpop/pop.key                   # → HEQK_POP_PUB for the S1 image
   ```
   This is a **test** key, used only for this tenant. Custody of the production PoP key is still open (ADR 0050 step 4).
   The A1 has no vTPM, so this key sits on disk.
5. **Allowlist** `/etc/superpop/devices`: only S1 test identities. Each line is `name  <ed25519 pk hex>  198.18.0.N`.
   The pk comes from the guest's `[ITEST] device identity pk=…` line. Never list a customer device.
6. **Service**: `sudo install -m 0644 deploy/superpop.service /etc/systemd/system/ && sudo systemctl daemon-reload &&
   sudo systemctl enable --now superpop`. Check: `ip -br addr show hqpop0` shows 198.18.0.1/15, `journalctl -u superpop`
   shows "N device(s) allowed", and `sudo nft list table ip superpop_nat` lists the masquerade rule.
7. **Rollback** (fully reversible): `sudo systemctl disable --now superpop` (the stop step removes its nft tables).
   Then revert the setup-vrf.sh PR, reload the table, and re-run security-patch.py. Remove the OCI ingress rule.

## How HookProbe Helps You Achieve More

### 1. Reclaim Your Time

Traditional security demands constant attention - alerts to investigate, logs to review, updates to manage. HookProbe handles this automatically so you can focus on your actual work.

- **Automated threat response** - attacks are dropped and recorded as evidence, no manual investigation needed
- **Customer-safe by design** - HookProbe blocks only a confirmed attack or flood; your legitimate traffic always passes
- **Signed, self-healing updates** - A/B slots with automatic rollback, so a bad update can't brick your box

### 2. Protect Without Complexity

Enterprise security usually needs a dedicated team. HookProbe OS needs **no Linux knowledge at all**:

```
1. Flash the image      →  one write with Raspberry Pi's own tools
2. Plug it in           →  network cable + power
3. Open Mission Control →  your browser, your device, your SOC
```

There's no `apt`, no `sudo`, no install script, no config files. The whole SOC runs on the device itself, standalone and air-gap capable, with **no account required**.

### 3. Scale Without Cost

One operating system for every deployment. The hardware only unlocks capabilities:

| Your Situation | What You Run | Investment |
|----------------|--------------|------------|
| Home network | One HookProbe OS box | Board only, $0 software |
| Small business | HookProbe OS on a dual-Ethernet CM5 carrier | Board only, $0 software |
| MSP / fleet | Many boxes, optionally enrolled to a control plane | Open core, commercial license for the hosted layer |

### 4. Own Your Security Data

Every security decision, every threat detection, every response action - it's all yours, stored sealed on your device. Export it. Analyze it. Verify it. No vendor has access unless you grant it.

## The Collective Defense Mesh

HookProbe's most powerful feature isn't code - it's community.

```
Node A (Singapore)     Detects zero-day attack
        │
        ▼
Mesh Intelligence      Validates pattern, creates signature
        │
        ├──────────────────────────────────────┐
        ▼                                      ▼
Node B (London)        Node C (New York)       Node D (Berlin)
Protected in <30s      Protected in <30s        Protected in <30s
```

**How it works:**
1. **Detection** - Any node detects a new threat pattern
2. **Validation** - Mesh consensus confirms it's legitimate
3. **Distribution** - Anonymized signature shared instantly
4. **Protection** - All nodes block the threat

**What we never share:**
- Your raw traffic data
- Your IP addresses
- Your internal network details
- Any personally identifiable information

**What we share:**
- Anonymized threat signatures
- Attack patterns (source removed)
- Model weight updates (federated learning)

Joining the mesh is **optional**. A HookProbe OS box enrolls over a post-quantum secure channel only if you choose to, and without it you still run a complete local SOC. This is collective defense that respects individual privacy.

## Inside HookProbe OS

HookProbe OS runs **zero Linux on the device**. Its foundation is **heqk**, our own Rust capability microkernel: the kernel *is* the network sensor, the IPS and the Mission Control web server.

```
                    IMAGE BUILD ENGINE                      os/build/
                           |
                PLATFORM-SPECIFIC PROFILES                  appliance/
                  /                   \
            CM5 TARGET             QEMU TARGET              appliance/cm5/ · os/kernel
                |                      |
          Signed boot             Signed image              Ed25519 + SLH-DSA boot signatures
          components              + manifest
                |                      |
          USB / WebUSB            Download image            tools/flash/ · os/provisioning/
          provisioning            raw / qcow2
                |                      |
          Hardware ID             Virtual ID                os/device-identity/
          and trust               and enrollment
                  \                   /
                   HOOKPROBE CONTROL                        onboarding/enrollment/
                           |
               Distributed Security Intelligence
```

| Layer | What it does | Status |
|-------|--------------|--------|
| **heqk microkernel** | Capability-secured Rust kernel; no Linux, no devicetree, nothing to patch but us | Running on CM5 hardware |
| **IPS datapath** | Inspects every packet; drops a confirmed attack, lets legitimate traffic pass | Proven on hardware |
| **Detection plane** | Standard RFC 9669 BPF rules plus signed WebAssembly detections in an isolated sandbox | Proven on hardware |
| **Mission Control** | The SOC console, served *by the device* to your browser, with owner-key sign-in | Proven on hardware |
| **Signed boot + A/B updates** | Hybrid Ed25519 + SLH-DSA (post-quantum) boot signatures, automatic rollback | Proven on hardware |
| **Sealed evidence store** | Detections encrypted at rest under a key bound to the chip | Proven on hardware |
| **Enrollment channel** | Optional, post-quantum hybrid (ML-KEM + X25519) channel to a control plane | Handshake proven on hardware; evidence export next |
| **Wi-Fi** | Access point or client, WPA2, run by heqk itself | Proven on hardware (bench builds) |

**Proven on hardware** means accepted on a real CM5: on 2026-11-04 the factory image booted, served Mission Control and dropped a live attack, which then appeared in the browser.

## Every Decision Is Explainable

Traditional security: "This is bad" (trust us).
HookProbe: every incident in Mission Control shows *what* happened, *why* it was flagged, the attack path, and the evidence behind it.

| Status | What It Means |
|--------|---------------|
| 🟢 GREEN | All clear · Protected |
| 🟡 AMBER | Monitoring · Stay alert |
| 🔴 RED | Under attack · Defending |

That band comes from **QSECBIT**, HookProbe's resilience score, computed on the device over a sliding window of what it has seen. **Shield**, the on-device DNS blocklist, answers blocked lookups locally and counts every query.

## ⚡ Get Started — Flash, Plug In, Protected

**What you need:** a Raspberry Pi **Compute Module 5** with eMMC on a carrier board (tested: Waveshare CM5-DUAL-ETH-MINI), a USB-C cable, and any Windows, macOS or Linux computer.

**1. Get the image.** Each HookProbe OS image comes with an **owner key** file (`.owner-key`), your device's sign-in key. Keep it safe; it's the only copy.
> 🚧 The first public signed image is not published yet. Watch [Releases](https://github.com/hookprobe/hookprobe/releases) or ⭐ star the repo to be notified.

**2. Flash it** with Raspberry Pi's own free tools:
- Set the carrier board's **nRPIBOOT / "disable eMMC boot"** switch and connect the board to your computer over USB.
- Run **rpiboot** ([raspberrypi/usbboot](https://github.com/raspberrypi/usbboot); use a current release, because older ones can't flash a CM5). The board's storage appears as a drive.
- Open **[Raspberry Pi Imager](https://www.raspberrypi.com/software/)** → *Choose OS* → *Use custom* → select the HookProbe OS image → choose that drive → *Write*. Skip Imager's OS customization: HookProbe OS doesn't use it.

**3. Plug it in.** Turn the nRPIBOOT switch back off. Connect the Ethernet port **furthest from the USB-C connector** to your router, then power the board.

**4. Open Mission Control.** Find the new device in your router's list of connected devices, browse to `http://<its address>/`, and sign in with the key from your `.owner-key` file.

**That's it.** No terminal, no commands, no account.

**⏱️ Time to protection:** minutes
**🔄 Updates:** signed A/B updates with automatic rollback
**💰 Software cost:** $0

> 🔜 **Coming next:** flash straight from your browser (WebUSB), with nothing to install.
>

## Architecture Overview

```
hookprobe/
├── os/                      # HookProbe OS: what runs on the device
│   ├── kernel/              # heqk, the Rust capability microkernel
│   ├── mission-control/     # the SOC console, served by the device
│   ├── build/               # image build engine: signed images
│   └── drivers/ networking/ security/ device-identity/ provisioning/   # guides into the code
│
├── appliance/               # Hardware profiles (cm5/, waveshare-dual-eth/)
├── onboarding/              # First boot: Wi-Fi, enrollment, setup UI
├── docs/                    # Architecture, getting started, security, roadmap, ADRs
├── tools/                   # Build, flash and diagnostics helpers
├── assets/                  # Logo and brand
│
└── legacy/                  # Previous implementations, full history kept
    ├── v1/                  # The original HookProbe (Python/Zig)
    └── linux-tier/          # The earlier Linux-based HookProbe OS
```

Every directory has documentation. Every module has a README. Moved from an older layout? See [`docs/PATHS.md`](docs/PATHS.md).

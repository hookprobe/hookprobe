## Proposals (operator decision; none implemented)

1. **Rule 121 — learn the established router.** Treat the RA sender that has been the LAN's default router
   (lifetime > 0) from the start as established; alert only on a NEW sender offering a default route (lifetime > 0)
   or on the established router's MAC changing. Expected: the 318 fortress RAs → 0.
2. **Rule 121 — lifetime-0 RAs are not rogue routers.** An RA with router lifetime 0 cannot become anyone's default
   gateway; report it as visibility (device kind: border router), not as an alert. Keep an alert when a lifetime-0 RA
   carries a Prefix Information option with the autonomous flag (SLAAC address injection) — this corpus cannot show
   the options (zeroed), so that half needs a synthetic test. Expected: the 585 Apple RAs → 0.
3. **Rule 127 — proxy ARP is not poisoning.** Do not alert when the claiming MAC is the established router / gateway
   (or one MAC claims ≥ 3 IPs whose own MACs stay active — the proxy-ARP shape); keep alerting when a non-router MAC
   takes over an IP, above all the gateway's. Expected: 10 → 0. (Today's exemption — a reply within 2 s of a who-has —
   misses unsolicited / late proxy replies.)
4. **Rule 116 — known-good egress.** Exempt Apple iCloud Private Relay egress (already recognised by Shield as a relay
   signal) from beaconing. Expected: 1 → 0. The bench SSH hit is a corpus artefact (label it, no rule change).

With 1–4: **0 alerts / 8.9 M frames** on this household day. Attack detection for the changed rules must be re-proven
with the synthetic attack corpus (`tools/detbench/gen-attacks.py`, CI) before any gate decision.

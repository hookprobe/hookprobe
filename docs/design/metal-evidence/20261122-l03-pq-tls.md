# L-03 — Mission Control negotiates the post-quantum hybrid TLS group (2026-11-22)

Bench CM5, image `am30S-8fdc26be` (main 2026-11-21 + E1b), Mission Control at https://192.168.200.146 (SNI heqk.local).
The 2026-11-14 assessment could not test this: the fortress host's OpenSSL 3.0 cannot offer ML-KEM. The bench host's
Node 24.18.0 ships OpenSSL 3.5.7, which can.

## Client side (`tools/diagnostics/cm5-tls-pq-probe.cjs`)

```
offered X25519MLKEM768: OK TLSv1.3 TLS_CHACHA20_POLY1305_SHA256 key exchange {}
offered X25519: OK TLSv1.3 TLS_CHACHA20_POLY1305_SHA256 key exchange {"type":"ECDH","name":"X25519","size":253}
```

Each connection offers exactly one group. A TLS 1.3 server can only choose a group the client offered, so the first
handshake completing means the device negotiated `X25519MLKEM768`. (Node reports no key details for hybrid groups.)

## Device side (serial console, the TLS server's heartbeat after the two probes)

```
[MC-TLS hb] ready=true calls=3208 handshakes=2 pq_hybrid=1 records_out=0 failed_closed=0 rate_limited=0 tls_errors=0 timeouts=0 faults=0 restarts=0
```

Two handshakes, one of them the post-quantum hybrid: exactly the two probes.

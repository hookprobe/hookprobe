## Failed / not proven

- **DEFECT (cfgd live revert target).** gen 3 (static WAN, dead gateway) failed its live trial; cfgd logged
  `reverting LIVE to the last-known-good` then `LIVE REVERT to generation 3` (expected 2), and after a reboot
  `HQCFG1 configuration bundle generation 3 in force (committed)` — the failed bundle became last-known-good.
  Root cause + fix in progress (QEMU reproduction first). C2/C3/E1–E3 and the spike / house checks are blocked on it
  and were stopped rather than run against a known-broken state.
- **C1:** a gateway-only WAN change was classed "management plane changed: waits for the owner's confirm". **By
  design**, not a defect: `cfgd::touches_mgmt()` requires the owner's confirm for any WAN section with `mgmt*` /
  `vlan` / `pcp` lines (presence-based); every bench WAN carries `vlan=100`. The check's expectation was wrong
  (fixed: C1 expects a needs-confirm trial, E2 confirms).
- **B3:** the Pi on the AP did not reach `10.100.0.1:8088` through the new static WAN, while fortress itself reaches
  it. Not yet diagnosed (routing/NAT on the static path vs the test).
- **Wi-Fi live spike, house test plan:** not run to completion (blocked by the defect above).

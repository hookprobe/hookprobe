## MB9 — Wi-Fi live spike + house plan on the PMKSA-fixed image — DEFECTS FOUND

- **Live security-MODE change fails in firmware:** the spike's WPA2-only round and its live revert to WPA3 transition
  logged `[WPA3] AP security WPA3 transition … wpa_auth 0x40080 set=false mfp 1 set=false` — the radio stays in a
  mismatched mode while the host believes WPA3 transition. Passphrase-only live changes are not affected.
- **Reject path loops:** SAE-AKM associations with no recorded SAE are rejected (`-> SAE with an unknown PMKID: reject`)
  but the deauth fails (`reason 49, ok=false`); the bench Pi loops (496 rejects vs 2 accepted SAE in the batch) — also
  after clean reboots (house 6.3, 8.3), so not only after the mode change. The per-boot SAE trace cap (64 lines) hides
  whether SAE completed before each association.
- House device side unchanged and passing (live apply, owner confirm, kept across reboots, old passphrase refused,
  sealed at rest); 6.2 was a check timing miss (serial shows `generation 2 in force (committed)` after the reboot).
- Firmware halts: 0.

Fix in progress (branch `fix/wpa3-reject-deauth`): live mode change brings the BSS down before setting
wsec/wpa_auth/mfp (or reports failure → revert), reason 20 for AKM/BSS mismatch, deauth fallback + error codes,
per-station SAE state in the reject log, per-station rate-limited SAE trace.

Nothing in this record marks a release gate complete.

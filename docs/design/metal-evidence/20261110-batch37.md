# Metal evidence — batch 37 (2026-11-10): WPA3-SAE on the AP, what this firmware does

Image P (`FEATX=wpa3probe`, SVN 11, bench build, never shipped): at AP bring-up the kernel sets
`wpa_auth=SAE (0x40000)`, `mfp=2` (required), tries `sae_password` (in-firmware SAE) and enables every
firmware event (`event_msgs_ext`), then logs each event on channel 1. The bench Pi's USB adapter (wlan1,
rtw88 on mac80211, SAE in software) scans and tries a WPA3-SAE join with PMF required.
Run with `tools/diagnostics/cm5-wpa3-probe-check.sh`. The Pi's saved passphrase was used but never printed.

## Verdict

| Question | Answer on this firmware (CYW43455, the RPi build) |
|---|---|
| Does it take an SAE AP configuration? | **Yes.** `wpa_auth=SAE` is accepted and reads back 0x40000; `mfp=2` is accepted. The beacon advertises WPA3 (nmcli `SECURITY WPA3`). |
| Does it run SAE itself (offload)? | **No.** `sae_password` is refused (`set=false`), the same answer as `[WIFI-CAP] sae=false`. |
| Does a station's SAE Authentication reach the host? | **Yes.** Every SAE attempt by the Pi arrives as firmware event **188 = `EXT_AUTH_FRAME_RX`** carrying the 802.11 Authentication frame (frame control `b0 08`, addr1 = AP BSSID, addr2 = the Pi wlan1), with three retransmissions per attempt (sequence `0000`, `1000`, `2000`). |
| Did the join succeed? | **No — as expected.** Nothing on the host answered the commit, so the Pi timed out after 5 s per attempt and NetworkManager gave up. |

**Conclusion:** WPA3-SAE on the AP is a **host build**, not a supplier dependency. The firmware takes the SAE
configuration and PMF and passes the authentication frames to the host. heqk already runs the WPA2 4-way
handshake on the host. The work left is:

- an SAE responder (commit and confirm over P-256);
- the authentication frames sent back through the firmware's management-frame transmit path;
- the SAE PMK feeding the existing 4-way handshake;
- PMF (IGTK).

Each step still has to be proven on metal. Until then, gate item NET-03 stays open as a build, not as a blocker.

Remaining uncertainty: the probe printed only the first 40 bytes of each frame, so the authentication algorithm
number (3 = SAE) and the commit body were not shown. The responder build prints them first.

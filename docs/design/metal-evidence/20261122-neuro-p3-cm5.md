# Neuro P3 on CM5: el0-neuro + the data-plane adapter on the AP, A/B against the same build without it (2026-11-22)

**Images.** Built from one tree (`feat/neuro-p2-dp-hooks` 78cb7095 = main with #1468 + P2):
- `am35B` = AP bench flavour + `wpa3`;
- `am35N` = the same + `neuro`.

**Load.** 20 min each, identical: the bench Pi on Wi-Fi resolves and fetches about 30 domains over HTTPS in a loop,
plus one NXDOMAIN lookup per round.

**Per-beat loop maximum.** Every beat's maximum includes the heartbeat's own synchronous UART printing, about
430 ms in both images.

| Metric | am35B (no neuro) | am35N (neuro) |
|---|---|---|
| beats | 244 | 244 |
| loop max per beat, p50 | 432 ms | 429 ms |
| loop max per beat, p95 | 439 ms | 448 ms (+9 ms) |
| loop max per beat, max | **5,339 ms** (one stall, see below) | 458 ms |
| `ap_poll` mean per call | 10.605 µs (81.3 M calls) | 10.605 µs (81.9 M calls) |
| panic / crash / el0-neuro supervisor event | none | none |

**Neuro counters at the end of the neuro window** (`[NEURO beat]`):
- the adapter saw **182,333 frames**;
- **14,935 events** were fed to el0-neuro in 30 batches, with **0 dropped**, 0 refused, 0 server resets and 0 slot
  evictions;
- 1 UTC hour closed, 0 failed, with 1 result marked deviant. That is the first hour of a device with no history, the
  cold start, and it is evidence only;
- peer rules: named 4,353 and class 1 (DNS names seen for nearly every connection); 18,829 A/AAAA answers learned;
- DNS timeouts 0, UDP evictions 0;
- 41 frames arrived before NTP sync and were counted, not attributed.

**Conclusion (this load).** Neuro costs nothing measurable on the AP loop: the median is equal, p95 is within 2%,
`ap_poll` is identical, and nothing was dropped or faulted. The payload fits (3,113,984 B against 3,137,736 B).

**Not shown yet:**
- per-excursion timing on CM5 (not instrumented);
- `[IDS-BENCH]` ns/packet (not printed by this flavour);
- fault injection into el0-neuro on metal;
- a multi-hour run, and the 64-device slot pressure.

**Baseline observation, not Neuro (explained).** The am35B window's 5.34 s loop max was the A/B script re-uploading
the running build: the device verified the staged 5 MB image (~5 s, synchronous in the AP loop) and only then refused
it as already running. Every gap jump on these boots sits right before `[OTA] new image written…`; with no upload, five
reboot rounds under light and heavy Wi-Fi traffic stay at 431–486 ms. Tracked as pre-soak finding 7 (OTA verify/install
should be incremental); not a soak risk.

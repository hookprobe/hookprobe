# Metal evidence — batches 38–47 (2026-11-10): WPA3-SAE on the AP, factory reset

Images W..W9 (feature `wpa3`, bench builds, SVN 11). Each round changed one thing; the console and the bench Pi's
wpa_supplicant (debug level for the attempt) are the evidence. The passphrase was never printed.

## WPA3-SAE: from "firmware forwards SAE" to a working join

| Batch | Change | What the metal said |
|---|---|---|
| 38 | Host SAE (hunting-and-pecking) + `mgmt_frame` TX | TX layout right: every `mgmt_frame` echoed its packet id in event 189 with status 0 (acked). But every commit was refused: the Pi uses **SAE-H2E** (status 126, "Derive PWE from PT"), and in transition mode its onboard profile also prefers SAE. |
| 39 | H2E (SSWU, PT, Rejected Groups salt) | `SAE … seq 1 status 126 group 19 -> Committed`, `seq 2 -> Accepted`; the Pi verified our confirm ("peer-send-confirm 1"). Association then refused by the firmware: reason 6 (class-2 frame from a non-authenticated STA) / status 16. |
| 40–42 | Firmware ext-auth completion (`auth_status`) | 802.11 status 0 in `flags` → BCME −2 (BADARG). `flags = WL_EXTAUTH_SUCCESS (4)` after `pmkid_info` → accepted. The station associates; the AKM-8 4-way runs; our M2 MIC verifies (SHA-256 PTK + AES-CMAC right). |
| 42–43 | M3 RSNE | wpa_supplicant: "IE in 3/4 msg does not match" — beacon RSNE `30 18 01 00 00 0f ac 04 01 00 00 0f ac 04 02 00 00 0f ac 02 00 0f ac 08 8c 00`; then "RSNXE mismatch" — the beacon also carries `f4 01 20` (SAE-H2E). |
| 44 | M3 = beacon RSNE ‖ RSNXE | **WPA3: PASS (6/6)** — `Key negotiation completed [PTK=CCMP GTK=CCMP]`, `IGTK keyid 4`, lease 10.99.0.10, gateway answers; AP `akm=SAE … m4_mic=true ptk_set=true authorized=true`. |
| 47 | Default WPA2; `HEQK_AP_SECURITY=wpa3` bench image (W9) and the default image (W9d) | **WPA3-only: `WPA3: PASS (6/6)`** (beacon RSNE caps `cc 00` + RSNXE; M3 matched first time) and the full LAN suite **`LAN-CLIENT: PASS (18/18)` over SAE** (the Pi's onboard brcmfmac keyed `akm=SAE`); then the WPA2-default image: **`LAN-CLIENT: PASS (18/18)`** with `akm=PSK`. |
| 45, 46 | Same, full regression | SAE 6/6 again (twice). **Transition mode refuses a WPA2-only (no-PMF) station**: open-system auth OK, then association rejected with status 38. A 2.4 GHz boot (after the factory reset) beaconed RSNE caps `0c 00` instead of `8c 00`. `WLC_GET_BSS_INFO` does not return our own beacon IEs in AP mode. |

Consequences, built in:
- The default stays **WPA2-PSK**, the unchanged path proven since September. WPA3 and transition are opt-in through `WIFI.TXT security=`.
- Transition mode is documented as excluding WPA2-only devices on this firmware.
- The M3 RSNE is the metal-observed beacon shape. The 2.4 GHz caps difference stays open (see below).

## Open
- 2.4 GHz caps: the M3 RSNE now takes MFPC/MFPR from the firmware's `mfp` read-back after bring-up (built, metal-pending).
- **Transition mode × WPA2-only stations.** The firmware rejects the association with status 38. Likely cause: the firmware's handling of a no-MFP RSNE while `mfp=1`, which needs a firmware-side answer or a per-mode `mfp` choice. Until it is resolved, transition mode stays opt-in.
- **2.4 GHz beacon caps (`0c 00`).** The M3 RSNE has to follow them; no firmware read-back exists in AP mode.

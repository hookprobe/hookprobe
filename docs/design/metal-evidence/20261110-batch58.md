# Metal batch 58 (2026-11-10/11): image W17 (a1486fe6), CM5 bench

Image: `imgW17` (feat/heqk-prod-phases a1486fe6). Features: `hboot,apmc,wifi-bigtx,appersist,wpa3`. No `HEQK_AP_SECURITY` is set, so the default applies.

## What passed on silicon

- **WPA3 transition mode is the default.** Boot log: `[WPA3] AP security WPA3 transition (WPA2-PSK + SAE, PMF capable)`, IGTK installed.
  - A WPA3 station joins with SAE H2E (status 126, group 19); the AP logs `-> Accepted`.
  - A WPA2-only station joins in transition mode with AKM PSK and no PMF.
- **WAN.TXT signature check:** `[WAN] WAN.TXT signature OK — operator key, generation 2`. The anchor is pinned on first use.
- **`[P-lansvc]` PASS on CM5, including:**
  - D4 step 2b: the DHCP server's request parse runs in EL0 with the same facts as in-kernel;
  - D4 step 3a: WAN DHCP OFFER, RA and DHCPv6 parse in EL0 give identical results.
- **Config journey (ADR 0058), A1–B8, 12/12:**
  - staged WAN upload (gen 12); a rollback with only one generation is refused;
  - `/api/reboot` applies the staged file, and the store copy verifies (gen 12);
  - gen 13 uploaded, then rollback re-activates gen 12;
  - owner-key enrollment: a bad proof is refused, enrollment succeeds, a second enrollment is refused;
  - after enrollment, a vendor-signed WAN.TXT is refused and an owner-signed one is accepted;
  - the next boot verifies the owner-signed WAN.TXT (gen 14).

## Failures and their causes

- **C2–C5 and D1: a real defect, fixed in 79634e49.**
  - The test: a signed WAN.TXT that removes the uplink and the management VLAN (vlan 999, no mgmt). The device applied it correctly (C3 ok).
  - The defect: the AP loop handled a station's IPv4 frames only while the WAN or the management VLAN was up. On the Wi-Fi AP, ARP was answered, but ping and HTTPS to 10.99.0.1 got no reply (Pi probe after the batch: ARP REACHABLE, 100 % ping loss, HTTP 000). This violates ADR 0058 rule 7.
  - The fix: frames to the AP address are always handled.
  - C4, C5 and D1 failed as a cascade: no rollback was possible, so there was no management VLAN, so the factory-reset step could not connect.
  - Re-run in batch 59.
- **LAN-client "Shield: example.org → NXDOMAIN" (17/18): the probe missed it.** The serial log shows the Shield blocked it for that client (`blocked=2 … last_blocked=example.org from 10.99.0.11`). Re-run in batch 59.
- **WPA3 check "AP accepted the SAE exchange" (6/7): outside the probe's capture window.** The serial log shows `[WPA3] SAE … -> Accepted` and the 4-way completed with the SAE PMK (AKM 8). Re-run in batch 59.

These are not counted as passes until the re-run confirms them.

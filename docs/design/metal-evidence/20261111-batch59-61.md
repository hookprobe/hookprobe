# Metal batches 59–61 (2026-11-11): CM5 bench

All three batches ran on the CM5 bench with the AP image (`hboot,apmc,wifi-bigtx,appersist,wpa3`). No
`HEQK_AP_SECURITY` was set, so the WPA3 transition default applied. Batch 61 used image W20
(feat/heqk-prod-phases 16906c8c).

## Batch 59: re-runs after the batch-58 rule-7 fix

Passed on silicon:

- **WPA3 transition default: PASS (7/7).** Boot log: `[WPA3] AP security WPA3 transition (WPA2-PSK + SAE, PMF
  capable)`, IGTK installed (algo 12).
- **LAN client: PASS (18/18).** This includes the Shield NXDOMAIN probe that the batch-58 probe missed.
- **WAN.TXT signature and anchor:** `WAN.TXT signature OK — operator key, generation 2`; the anchor was pinned on
  first use.
- **On CM5:** `[P-lansvc]`, `[P-hsh]` and `[P-mgmtabi]` PASS. The DNS parser runs in EL0 (665 messages, one
  deliberate fault, one restart, 0 in-kernel).

Failed:

- **Config journey: 16/20.** C2, C4, C5 and D1 failed. The image predates the rule-7 fix (frames to the device
  address are handled with no uplink). Re-run in batch 61: passes.
- **cfgd check: 3/12.** A1 had no response captured, and the rest followed from it. Batch 60 printed the refusal
  reasons so the cause was visible.

## Batch 60: cfgd defects found

- **A boot self-test committed a live trial.** cfgd showed `committed` instead of `trial` on the first boot after
  the upload. Fixed in b5a96675: confirm and revert refuse while a self-test is running.
- **Other defects, fixed in 16906c8c:**
  - after a factory reset, the WAN floor was kept, so the device refused its own shipped WAN.TXT;
  - a per-file WAN upload was silently ignored while a bundle was in force.

## Batch 61: image W20 (16906c8c)

- **`[P-lansvc]`, `[P-hsh]` and `[P-mgmtabi]` PASS on CM5.** This includes D4 step 3b (PPPoE / LCP / IPCP / CHAP /
  IPv6CP parsing in EL0) and 4c (HQCHAL1 owner elevation).
- **Config journey (ADR 0058): PASS (20/20).**
  - A: staged WAN upload, rollback, reboot.
  - B: owner-key enrollment, then owner-signed configuration only.
  - C: a disconnecting WAN.TXT:
    - Mission Control still answers on the Wi-Fi AP (rule 7);
    - rollback from the Wi-Fi client;
    - the device comes back on the management VLAN.
  - D1: factory reset keeps the enrolled owner key (FACTORY-RESET 9/9).
- **cfgd (ADR 0059 step 3): 11/13.**
  - Passed:
    - an HQCFG1 bundle staged, booted as a trial and waited for the owner (it touches the management plane);
    - the owner's confirm committed it, and it was in force (committed) after a reboot;
    - rule 7: Mission Control stayed reachable on the AP;
    - the device returned to the last-known-good;
    - cleanup rollback.
  - **B1 / B3 failed: a real defect, fixed after this batch.** After a committed bundle, the next bundle upload was
    refused with `rollback refused: generation older than the active pack`. `artstore::active_gen` read the
    generation from signature bytes [8..16]. Other pack signatures carry it there; HQCSIG1 does not (alg | length |
    digest), so the result was garbage. The fix: a bundle's active generation comes from the store manifest, and
    `[P-cfgd]` asserts it. B3 (automatic revert after the window) was not exercised, because the bundle never
    staged. Re-run is pending.

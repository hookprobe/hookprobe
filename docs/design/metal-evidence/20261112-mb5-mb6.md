## DEFECT found — WPA3 reconnect with PMKSA caching

A WPA3 client that reconnects with a cached SAE PMKSA (open-system auth + RSNE AKM 8 + PMKID, no SAE exchange) is keyed
by the AP as WPA2-PSK (passphrase PMK, AKM 2); the client never sends M2 and deauths. Root cause:
`kernel/src/main.rs` ~4378 chooses PMK/AKM from "did this station just complete SAE" (`ap_sae_pmk`), never from the
station's association RSNE. SAE state is cleared on every BSS restart / reboot / reflash, so every previously-connected
WPA3 client fails to reconnect until its cache expires (iPhone: "reconnected after a timeout" / "after joining another
network"). Evidence, both sides:
- AP: `[P11-AP3 auth] akm=PSK m1_sends=2 m2_rx=false … deauth=true` for iPhone `36:83:6b:…` and the bench Pi, repeated.
- Pi wpa_supplicant (DEBUG): `RSN: PMKSA cache entry found - PMKID …`, `using KEY_MGMT SAE`,
  `SAE: Use WPA_AUTH_ALG_OPEN for PMKSA caching attempt`; after failures `Delete PMKID` → full SAE → success.
- The house / spike Pi-join failures in MB4/MB5 were this defect (not the configuration bundles): the same Pi joins the
  known-good image at once, and joins imgM5 whenever it performs a full SAE.
Fix in progress (branch `fix/wpa3-pmksa-reconnect`); metal retest with the Pi and the operator's iPhone follows.

# Metal evidence — 2026-11-14 night (CM5 bench; Pi client on wlan0, Pi monitor on wlan1)

All images were built from main plus the named change and installed by OTA (`cm5-ota-check.sh`, 9/9 each).

## 1. DNS-01 fixed: the AP's own replies are held 20 ms before the firmware (#1187)

Method: a Pi client (wlan0); 20 unique sinkholed names (`tN.<blocked domain>`, all NXDOMAIN) with 5 benign names
interleaved; 2 s apart; `dig +tries=1 +time=10 @10.99.0.1`.

| Image | Sinkholed (locally built reply) | Benign (forwarded) |
|---|---|---|
| main `rl1` | 6/20 > 10 s (timeout), 6/20 2.3–5.8 s, 3/20 0.18–0.89 s, 5/20 3–7 ms | 3–39 ms |
| `dfr20` (+ 20 ms hold) | **20/20 in 23–27 ms**, 0 timeouts | 3–39 ms (one 227 ms upstream outlier) |

- **Root cause:** a frame the host builds and hands to the CYW43455 firmware within ~0.1 ms of the station's
  uplink frame is often held by the firmware for seconds, until the station's next uplink. Forwarded answers, one
  upstream round trip later, are never affected.
- **Disproved alternative:** the same reply sent after the host drained all pending RX (image `dns2`) was still
  held, by more than 6 s.
- Reported to Infineon.

## 2. DFS auto-channel and the OTA commit gate during CAC (#1158, #1157)

Image `p4a`: main + #1187 + `HEQK_AP_DFS=1` + a bench-only patch that ignores the device's WIFI.TXT channel (the
bench WIFI.TXT pins channel 36).

```
[P11-ACS] DFS channels considered (HEQK_AP_DFS=1): choice 0xe03a dfs=true ~433 Mbps; non-DFS best 0xe02a ~216 Mbps (the fallback)
[P11-AP2] try 1: channel 52 chanspec 0xe03a
[P11-DFS] AP on DFS chanspec 0xe03a: the firmware runs the CAC (~60 s, AP silent) — watching; fallback 0xe02a
[OTA] this boot: Trial(98) build=p4a-7c926f3e — TRIAL ... not during a DFS CAC ...
[OTA] trial: Wi-Fi DFS state Some(1) (AP NOT serving)
[OTA] trial: Wi-Fi DFS state Some(2) (AP may be serving)
[P11-DFS] CAC done — AP in service on DFS chanspec 0xe03a (dfs_status Some(2))
[OTA] COMMITTED slot b ...
```

- Auto-channel left the UNII-1 block, which the bench's fortress AP crowds, for 52/80.
- The trial treated the CAC as "not serving" and committed only after the AP was in service.
- The DFS watch reported in-service.
- The Pi client (Broadcom) followed to 5260 MHz, got a lease, and resolved a benign name in 7 ms. The rejoin took
  ~56 s, most of it the CAC, during which the AP is silent.

## 3. W-02: WPA3-only requires PMF (image `p4b`, `HEQK_AP_SECURITY=wpa3`, ch36)

- Firmware: `[WPA3] AP security WPA3-SAE (PMF required) — wpa_auth 0x40000 set=true mfp 2 set=true`.
- The Pi monitor captured 286 beacons: RSN AKM 8 (SAE) only, MFPC=1, **MFPR=1**, pairwise CCMP-128.
- A PSK-only client profile is refused, as it must be.

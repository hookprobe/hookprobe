# L0.1 firmware separation (`fwfiles`) — batch B1 evidence, 2026-11-20

Scope: ADR 0067 D11 / build-plan item L0.1 step 2. Branch `feat/l01-fw-integration` (on top of the boot-degraded fix).
Bench: CM5 over OTA only. **No rpiboot flash was done**; the cases that need a boot partition with the files present,
truncated or altered on the device are proven in QEMU against the factory-built disk image and are marked so.

build loses nothing permanently, but cannot run that build.

## 4c / 4d / 4e in QEMU — `os/kernel/tools/fwfiles-fat-cases.sh` on the am22F disk image

The read-only check kernel (the one the image factory boots) against copies of the image with the boot partition
changed by mtools. The device's own MBR + FAT code and the pins of the tree decide; `[P-fwfiles-fat]` prints what the
boot load would report. The boot load and this phase share one reader (`fwfiles::stream_file`); the boot load then
verifies the copy in memory, the phase hashes while reading.

```
ok  untouched image: all three files accepted                      Ok(())
ok  firmware absent -> Missing(0)                                  Err(Missing(0))
ok  firmware one byte short -> Size(0)                             Err(Size(0))
ok  firmware one byte long -> Size(0)                              Err(Size(0))
ok  firmware same length, one bit changed -> Digest(0)             Err(Digest(0))
ok  NVRAM absent -> Missing(1)                                     Err(Missing(1))

FWFILES-FAT-CASES: PASS (9/9)
```

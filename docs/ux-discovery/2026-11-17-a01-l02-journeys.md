# User journeys: A-01 (upstream private networks) and L-02 (Mission Control certificate names)

Status: **proposal**, 2026-11-17. Inputs:
- the operator decisions of 2026-11-17 (A-01: block upstream private networks by default, with owner exceptions; L-02: keep `heqk.local` and `10.99.0.1`, add the reserved management IP `192.168.200.146`);
- what the device does today, read from source (cited below).

Scope: backend and behaviour. Mission Control screens belong to the designer / Mission Control session. This document names the states and API fields those screens need.

## Personas

- **Home owner.** Non-technical. Put HookProbe behind the ISP router. Has a printer, a NAS or smart TV, or the ISP router's admin page on the upstream network. Wants "it just works" and is scared by browser warnings.
- **SMB operator.** Technical. Manages the device through the management VLAN. Uses signed configuration bundles (HQCFG1, POLICY ACLs). May renumber networks. Wants auditable, scoped changes.

## What the device does today (facts)

| Fact | Source |
|---|---|
| A Wi-Fi client's frame to an upstream private address is routed and NATed like any internet frame. Nothing blocks it today. | `apcore::forward4` |
| Per-device policy exists: `full`, `internet_only`, `lan_only`, `quarantine` (owner journal / `DEVICES.TXT`). It is checked per frame by destination class (`Dest::Internet / Lan / DeviceMgmt / Infra`). | `devpolicy.rs` |
| The owner-rules API (`/api/owner-rules`) writes owner-journal records. It takes `kind` (`device_policy`, `shield_allow`, `shield_block`, `shield_profile`), `target`, `value`, a required `reason`, `permanent=true` as explicit confirmation, owner-key re-authentication, a strictly increasing `seq`, CSRF, and `dry_run=1` for a preview. Refusals go to a RAM ring. | `ownerapi.rs` |
| An ACL `block` answers the client at once (TCP RST / ICMP admin-prohibited): the browser shows "refused", fast. A `drop` is silent: the browser waits about 30 s. | `apcore.rs`, `reject.rs` |
| Blocks are **counted** (`pol_block` per interface in the beat log) but **not attributed**: no record says which device tried which address. Mission Control cannot show "your printer was blocked". | `FwdCounters` |
| The TLS certificate is minted at provisioning by the **offline** local CA (name-constrained). The device cannot re-issue it. | `tools/provisioning`, `mctls-provision.py` |
| **Nothing resolves `heqk.local`**: no mDNS responder, and the device's DNS does not answer it. Most operating systems resolve `.local` only over mDNS. Owners therefore reach Mission Control **by IP address**. | grep: only the cert SAN and an HTTP redirect use the name |
| The management address comes from upstream DHCP (`mgmt=dhcp`). `192.168.200.146` is a reservation on the upstream router, not something the device decides. | bench WAN config |

## Journey 1: home owner, "my printer stopped working after the update" (A-01)

### Current state, if A-01 shipped as a bare default block
| Phase | Action | Touchpoint | Thinking / feeling | Pain |
|---|---|---|---|---|
| Trigger | Prints from a laptop on HookProbe Wi-Fi | OS print dialog | "Print." Neutral | — |
| Failure | The job fails, or the NAS share does not open | OS error ("printer offline") | "The printer broke?" **Confused** | The error names the printer, not HookProbe |
| Search | Reboots the printer, the laptop, the router | Physical devices, web search | **Frustrated**, 15–60 min | Nothing points to the cause |
| Discovery | Maybe opens Mission Control | MC dashboard | "Nothing about printing here." | Blocks are counted, not attributed: MC cannot say what happened |
| Resolution | Unplugs HookProbe, or calls support | — | **Abandons** the product's protection | A security feature removed by the user is a net loss |

**Moment of truth:** the first failed attempt after the update. If HookProbe cannot explain it at that moment, the owner blames the product and turns it off.

### Desired state
| Phase | Action | Touchpoint | Feeling | Design opportunity | Metric |
|---|---|---|---|---|---|
| Before | The update notes say: "Wi-Fi devices can no longer reach devices on your router's network unless you allow them" | Release notes; MC "what changed" card | Informed | A one-time notice after the update | % of owners who saw the notice |
| Failure | The print fails | OS dialog | Mildly confused | Fast refusal (ICMP / RST), not a 30 s silent wait | refusal latency < 100 ms |
| Explanation | MC shows: "**Blocked:** Laptop (kids-laptop) → 192.168.1.50 (port 631, printing), 3 times, last 2 min ago" | MC "Network access" card; optional alert hook | "Ah, that's the printer." **Understands** | Attributed block records (device, destination, port, count, first / last) | median time from block to understanding |
| Fix | Clicks "Allow **this device** to reach **192.168.1.50**", picks a duration (1 h / 1 day / always), re-enters the device password | MC, owner re-auth | **In control** | Scoped exception: device × destination [× port] × expiry, with a dry-run preview of what it opens | 1 click + re-auth; % of exceptions that are scoped (not "everything") |
| After | Printing works; the exception is listed and can be revoked | MC "Network access" list | **Confident** | Audit: who, when, why; expiry | exceptions revoked or expired vs kept |

## Journey 2: owner manages exceptions (A-01)

Common jobs:
- reach the ISP router's admin page once;
- let the family NAS / printer be reached by everyone;
- let one work laptop reach the office VPN box on the upstream LAN.

| Need | Proposed exception shape | Why it is safe |
|---|---|---|
| "Let me open my router's page, just now" | device × router address, **1 hour** | Expires on its own; scoped to one device |
| "Everyone may print" | **any device** × printer address × printer ports (631, 9100) | One host and specific ports, not the whole network |
| "My laptop needs the whole home network" | device × upstream private (all) | Explicit; shown as broad in red; requires re-auth and a reason |

Rules that keep security intact:
- **Default deny stays.** No exception exists without an owner action. Exceptions never come from code, a planner or a detection.
- **The management network is never exceptable.** Its subnet, the management gateway and the device's own addresses are refused by the API with a clear reason. This protects the management path (an existing hard rule).
- **Quarantine and `internet_only` devices** cannot be granted upstream access by an exception. An owner rule may tighten, never bypass a stricter device policy; it shows as `shadowed_by`, as today.
- **Every grant is a journal record** with a reason and an optional expiry, re-auth and CSRF as for every owner rule. Expiry is enforced on the device clock. Refused attempts stay in RAM only.
- **SMB operators** get the same exceptions through signed POLICY ACL `allow` entries (bundle-signed). Both paths show in one list, labelled with their source (owner / policy).

## Journey 3: owner reaches Mission Control by a new address (L-02)

### Current state
| Phase | Action | Feeling | Pain |
|---|---|---|---|
| Change | The upstream DHCP reservation changes, or the owner moves the device to another network | Neutral | The device cannot re-issue its certificate (the offline CA) |
| Access | Types `https://<new IP>` | — | The browser shows a full-page "**Your connection is not private**" (name mismatch) |
| Decision | Clicks through the warning, or gives up | **Anxious**: "is my security box hacked?" | Teaches owners to click through TLS warnings, which is exactly the habit we must not create |
| Alternative | Tries `https://heqk.local` | — | Does not resolve today: nothing answers it |

### Desired state
| Phase | Action | Feeling | Design opportunity | Metric |
|---|---|---|---|---|
| Access | Types `https://heqk.local`, bookmarked from setup | Confident | An **mDNS responder** for the device name on the AP and management interfaces. The name works whatever the IP is, so the certificate never needs re-issuing for an address change | % of MC sessions arriving by name vs IP |
| Several units | `https://hookprobe-<id>.local` | Confident | A **unit-unique name** in the SAN (in addition to `heqk.local`) so two units on one network do not collide | name collisions = 0 |
| By IP | `https://192.168.200.146` (the reserved address) works without a warning | Confident | L-02 (done on the bench) | — |
| Mismatch | If MC is reached by a name or IP not in the certificate (after the click-through), it shows a banner: "use `https://heqk.local` or `https://10.99.0.1` (Wi-Fi) — this address is not on the device certificate" | Guided | `Host` check against the SAN list; the SAN list in `/api/health` | click-through sessions trending to 0 |
| Renumber (SMB) | Re-provisions the certificate with the operator CA (documented command) | In control | `provision-unit.py --tls-ip …`; MC shows the certificate's names and expiry | — |

What we do **not** propose: an on-device CA or self-issued IP certificates. A device able to mint certificates for private addresses would let a compromised unit impersonate other local hosts to every browser that trusts the owner CA. The name-based path avoids that cost.

## API fields for the Mission Control session (proposal)
- `GET /api/lan-access`: `{ "default": "block", "blocked": [{ "mac", "label", "src_ip", "dst", "dport", "proto", "count", "first_ts", "last_ts" }], "exceptions": [{ "id", "source": "owner" | "policy", "device": mac | "any", "dst": prefix, "ports": [..] | null, "expires_ts" | null, "reason", "created_ts", "effective", "shadowed_by" }] }`
- `POST /api/owner-rules` with `kind=lan_access`, `op=set|remove`, `target=<mac|any>`, `value=<prefix>[:ports]`, `expires=<seconds>|permanent`, plus the existing guards (reason, owner_key, seq, CSRF, `dry_run`).
- `GET /api/health` → `"tls": { "names": [...], "ips": [...], "not_after", "ca_fingerprint", "request_host_covered": bool }`.

## Decisions requested from the operator
1. **Exception shape:** device × destination [× ports] × expiry, as above, with "any device" allowed for a single host. Recommended.
2. **Default expiry offered first:** 1 hour, "always" only on explicit choice. Recommended.
3. **mDNS responder** for the device name on the AP and management interfaces. Recommended; no certificate change.
4. **Unit-unique `.local` name added to the SAN at provisioning**, alongside `heqk.local`. Recommended for multi-unit sites; it changes the provisioning default.
5. **IPv6 ULA (fc00::/7)** counts as "upstream private" under A-01. Recommended, for parity with RFC 1918.

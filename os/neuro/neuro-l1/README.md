# neuro-l1: DNA v1 in fixed point + the frozen S1 integer twin (candidate, not deployed)

**Status: research artefact.**
- M3 (doc 31) failed S1's recall gate.
- Doc 35 proposes M4, which tests the **frozen** S1 model on new sealed IoT data.
- This crate makes the integer path measurable for that test and gives a later EL0 L1 server a reviewed core.
- The kernel does not use it. No model reaches a device without a sealed pass and a signed package (heqk D3).

## What it is

| Part | What |
|---|---|
| `HourAgg::add(&Conn)` | one connection per call. The fields are those `tools/neuro-research/bench/dna_features.py` reads from a flow event; peers are fingerprints with a LAN flag, and "novel" is decided by the caller from its 24 h memory |
| `HourAgg::quantise()` | the 28 S1 features as u8, quantised as `tools/neuro-research/models/s1/s1_model.json` does |
| `score()` / `alert()` | the frozen weights: i16 × u8 + i32 bias, alert iff accumulator > threshold |
| `src/s1_model.rs` | generated by `tests/gen_model.py` from `s1_model.json` (SHA-256 `20f38f33…`) |

**Arithmetic.**
- Integers only.
- `log2` in Q32 by repeated squaring (exact on powers of two, within 2^-31 elsewhere).
- Integer square root; i128 intermediates.
- No float, no allocation, no `unsafe`.

| IoT-23 test windows from captures ≤ 4 GB, streamed (spent by M3; local) | 219 | **0** | 82 of 6,132. All 54 differences above 1 are in windows past the peer bound (9-1 and 35-1 scanning bots, 300k–460k peers per hour): periodicity (features 22/23) and the linear-counted peer count (feature 2) |

Within the bounds, every difference is 1 quantum. These come from the reference rounding its float vector to 5 decimals before
quantising, while this crate quantises exact Q32 values.

## Bounds (each counted in `Overflow`)

- **Peers:** 3,072 distinct peers with counts. More are counted by linear counting (32 Kbit) and miss the periodicity
  log.
- **Ports:** 1,536 destination ports with counts. More are counted exactly as distinct ports, and as singletons in
  entropy and top share.
- **Periodicity log:** the first 16,384 connections of the hour, as (peer, time). The reference keeps each peer's
  first 400 times.

## Open items before any device use

1. **Memory.** One `HourAgg` is **228 KiB**, mostly the periodicity log (128 KiB) and the peer table (80 KiB).
   That is fine for one aggregate at a time on the host. It is not fine as 64 resident per-device aggregates in
   el0-neuro's 4 MiB window. A device design keeps times only for heavy-hitter peers (space-saving, K ≈ 16) and
   re-measures parity.
2. **Input.** `neuro-dp` does not produce per-connection summaries today (doc 34 §4). They are needed only if a model
   passes M4.
3. **Connection rule.** The reference vectors are Zeek-cut. On a device the connections are cut by `neuro-dp`'s
   doc 20 rule. Doc 34 §2 measured the benign side.
